## 1. Overview

Redis is a critical infrastructure tier in SmartQueue AI, serving as the high-throughput distributed lock manager, fast cache store, real-time queue index, and session state store.

Because the system simulates flash-sale reservation spikes handling thousands of concurrent requests per second, Redis is configured for low latency, sub-millisecond atomic operations, and deterministic memory eviction policies.

## 2. Key Naming Convention

Redis keys across all microservices must conform to a standardized, colon-delimited namespace hierarchy:

```text
smartqueue:<service>:<entity_type>:<entity_id>[:attribute]
```

### 2.1 Examples by Domain

| Domain | Key Pattern | Type | Example |
|---|---|---|---|
| Distributed Seat Lock | `smartqueue:inventory:seat-lock:<eventId>:<seatId>` | String | `smartqueue:inventory:seat-lock:evt-101:seat-12B` |
| Reservation Hold | `smartqueue:booking:hold:<reservationId>` | Hash | `smartqueue:booking:hold:res-8821` |
| Flash-Sale Queue | `smartqueue:queue:waiting-list:<eventId>` | ZSet | `smartqueue:queue:waiting-list:evt-101` |
| JWT Blacklist | `smartqueue:auth:token-blacklist:<jti>` | String | `smartqueue:auth:token-blacklist:jti-8f92a1b4` |
| User Session State | `smartqueue:realtime:session:<userId>` | Hash | `smartqueue:realtime:session:usr-501` |
| Event Seat Map Cache | `smartqueue:inventory:seat-map:<eventId>` | String (JSON) | `smartqueue:inventory:seat-map:evt-101` |

## 3. Distributed Locking Strategy

To guarantee **zero double-bookings** during concurrent seat reservation attempts, SmartQueue AI implements single-instance Redis atomic locking (`SETNX` with Lua script release) and multi-node Redlock consensus for high-availability production clusters.

### 3.1 Lock Acquisition Algorithm (`SETNX`)

1. **Acquire:** Execute atomic `SET key value NX PX <ttl_milliseconds>`:
   ```bash
   SET smartqueue:inventory:seat-lock:evt-101:seat-12B "uuid-client-1" NX PX 15000
   ```
2. **Value Check:** The lock value is a unique UUID generated by the client to prevent a process from releasing a lock acquired by another thread.
3. **TTL Safety:** Locks enforce an explicit TTL (default: 15,000ms / 15s) to guarantee automatic recovery if a worker node crashes mid-transaction.

### 3.2 Atomic Lock Release (Lua Script)

Locks are released exclusively using an atomic Lua script that verifies token ownership before deletion:

```lua
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
```

## 4. Cache Strategy & Patterns

### 4.1 Cache-Aside (Lazy Loading) for Seat Layouts
- **Read Flow:** Query Redis first (`smartqueue:inventory:seat-map:<eventId>`). On cache hit, return JSON payload immediately. On cache miss, query PostgreSQL database, populate Redis with explicit TTL, and return payload.
- **Invalidation Flow:** When a seat status changes (`AVAILABLE` -> `HELD` -> `BOOKED`), publish a cache invalidation signal via Redis Pub/Sub to refresh cached layouts.

### 4.2 Write-Through for Available Seat Counters
- Available seat counts for active events are tracked as atomic Redis integers (`DECRBY`, `INCRBY`) to evaluate event sold-out status instantly without hitting PostgreSQL.

## 5. Flash-Sale Queue Storage (`ZSET`)

During flash sales, excess user traffic is queued using Redis Sorted Sets (`ZSET`).

- **Score Indexing:** The score represents the precise timestamp (in milliseconds) when the user entered the queue.
- **Queue Operations:**
  - `ZADD`: Add user to queue (`ZADD smartqueue:queue:waiting-list:<eventId> <timestamp> <userId>`).
  - `ZRANK`: Query user's real-time queue position.
  - `ZPOPMIN`: Admit the top N users from queue to booking page per batch window.

## 6. Standardized TTL Policy Matrix

All non-persistent keys stored in Redis **must** specify an explicit TTL to prevent memory leaks and out-of-memory (OOM) crashes.

| Data Type | Key Pattern | Default TTL | Memory Policy |
|---|---|---|---|
| Distributed Seat Lock | `smartqueue:inventory:seat-lock:*` | 15 Seconds | `noeviction` |
| Temporary Seat Hold | `smartqueue:booking:hold:*` | 10 Minutes | `volatile-lru` |
| User Session State | `smartqueue:realtime:session:*` | 24 Hours | `volatile-lru` |
| JWT Token Blacklist | `smartqueue:auth:token-blacklist:*` | Token Expiry Time | `volatile-lru` |
| Cached Seat Map JSON | `smartqueue:inventory:seat-map:*` | 1 Hour | `allkeys-lru` |
